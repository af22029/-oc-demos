# 文字ミキサー（高校生向けデモ）

手書き数字（MNIST）を VAE で学習し、**潜在空間＝文字の地図**を体験させるデモ。
`D:\蝉音声デモ_高校生向け\`（蝉ミキサー）とは**完全に独立**した別プロジェクト。共有ファイルはなし。

## 使い方（当日）

`デモを開く.bat` をダブルクリック → ブラウザが開く。Python も GPU もネットも不要。

- **① 文字の地図**：背景はすべて AI がその場で生成した文字。クリック・ドラッグで移動。点は本物のMNIST（数字ごとに色分け）
- **② 自分の字を置く**：パッドに数字を書いて「AIに見せる」→ 判定・整えた入力・AIの復元・地図上の★位置を表示
- **③ モーフィング**：3→8 のように数字から数字へ連続変化。途中は存在しない文字
- **④ しくみ**：VAE の説明と実測正答率

## 精度について（設計判断）

| 潜在次元 | 判定の正答率 | 地図としての見やすさ |
|---|---|---|
| 2次元 | 約 75 % | そのまま地図になる |
| **8次元（採用）** | **約 91 %** | PCA の2次元平面で切って表示 |

2次元だと 4と9、3と5と8 が地図上で重なり、原理的に区別できなくなる。
そこで潜在は8次元にし、**地図は「8次元空間を通る2次元平面の断面」**として描いている
（`z = mean + a·PC1 + b·PC2`）。クリックした座標と生成される文字は厳密に一致する。
判定（k-NN）は8次元空間そのもので行うので精度が落ちない。

正答率が100%でないのは、ラベルを一切使わない**教師なし学習**だから。ここは欠点ではなく説明の材料。

## 手書き入力の前処理（MNIST 規格に合わせる）

`web/index.html` の `preprocess()` が以下を実施：

1. 描いた部分を切り出し、縦横比を保って長辺 20px に収める
2. 3×3 ぼかしで MNIST のアンチエイリアスに寄せる
3. **ガンマ補正でインク量を MNIST 平均 0.1307 に合わせる**（＝線の太さの正規化。大きく書いても小さく書いても同じ濃さになる）
4. **重心を (14, 14) に平行移動**（MNIST は外接矩形ではなく重心で中央化されている規格）

3 と 4 を入れる前は、7 や 1 のように重心が偏る字、線の太さが極端な字で外れやすかった。

## モデルを作り直したいとき

```bash
python engine/train_mnist_vae.py                 # 潜在8次元・40 epoch（GPUで約2分）
python engine/train_mnist_vae.py --zdim 2        # 2次元版（精度75%だが地図がそのまま潜在）
python engine/train_mnist_vae.py --beta 0.5      # KLを弱める＝数字ごとの塊がはっきりする
```

MNIST は `engine/mnist_cache/` に自動ダウンロード（初回のみ要ネット、12MB）。
出力は `web/data/mnist_vae.js`（5.9MB）で、重み・PCA基底・判定用の実データ潜在ベクトルを base64 float32 で格納。
ブラウザ側の JavaScript がエンコーダ／デコーダを直接計算するため、**配布時に Python は不要**。

## 他のPCで使うには

`web` フォルダ（約6MB）をコピーして `index.html` を開くだけ。`engine` は再学習用なので配布には不要。

## 検証済みの数値

- Python 実測 5-NN 正答率：91.4 %（テストデータ3000枚）
- 同じ計算を JavaScript 実装で再現：94.3 %（テストデータ300枚）→ ブラウザ側の forward 計算が正しいことを確認済み
- PCA 寄与率：PC1 0.161 / PC2 0.141（地図が表示できるのは8次元の情報のうち約30%）
